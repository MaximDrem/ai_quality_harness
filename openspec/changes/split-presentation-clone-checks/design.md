## Context

Метрика в scoring считается как `pass/all` по всем проверкам с одним именем. Одиночный агрегированный handler всегда даёт 0 или 1 и не показывает, какой именно аспект оформления или чистоты нарушен.

## Goals / Non-Goals

**Goals:**

- каждая метрика M1/M3/M5 состоит из независимых проверок;
- каждый провал имеет отдельную причину в XLSX;
- пакетные проверки PPTX находятся в PPTX-domain;
- сохранить текущее поведение на fixture-примерах.

**Non-Goals:**

- менять формулу scoring;
- вводить новый judge-профиль;
- реализовывать визуальные проверки наложений и уменьшения шрифта.

## Decisions

- M1 разделён на формат заголовка и совпадение имени: неправильный заголовок и правильный заголовок с чужим именем — разные причины.
- M3 разделён по структурным аспектам: canvas, master/theme, все layouts, использованные layouts, шрифты текста и цвета текста.
- Стили текста сравниваются по фактическим слайдам шаблона, а не по всему PPTX-пакету: theme-шрифт или служебная палитра не легализуют шрифт/цвет, отсутствующий на слайдах шаблона. Для цветов дополнительно допускается активная цветовая схема темы.
- M5 разделён по источникам следов: видимый текст, метаданные и relationships. Неиспользуемые layouts и темы по-прежнему не сканируются.
- Общая XML-логика вынесена в приватальные PPTX-helpers и не регистрируется как handler.

## Risks / Trade-offs

- [Число проверок возрастает] → Веса метрик не меняются, вклад метрики определяется `pass/all`.
- [Разные проверки дублируют чтение пакета] → Прогон offline и объёмы PPTX незначительны; независимость причин важнее.
- [Разделение увеличивает YAML] → Группы остаются декларативными и подключаются одним именем.

## Migration Plan

1. Добавить независимые handlers и приватальные helpers.
2. Удалить агрегированные handlers.
3. Обновить метрики и тесты.
4. Проверить fixtures, offline-suite и OpenSpec.
