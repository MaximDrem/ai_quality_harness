# presentation-clone Delta

## ADDED Requirements

### Requirement: Индивидуальные проверки заданий на шаблонах Slidesgo

Сценарий клонирования презентации SHALL включать кейсы `US01-01-01…06` на шаблонах AI Technology и Remote Working и для каждого кейса проверять число слайдов, обязательную структуру и факты, заданные ограничения содержания и язык.

#### Scenario: Кейсы используют предусмотренные шаблоны Slidesgo

- **WHEN** загружаются кейсы `US01-01-01…06`
- **THEN** кейсы `01…03` используют AI Technology
- **AND** кейсы `04…06` используют Remote Working

#### Scenario: Финал соответствует индивидуальному заданию

- **WHEN** финальная презентация содержит заданное число слайдов, обязательные разделы и факты, соблюдает ограничения и язык кейса
- **THEN** индивидуальные проверки следования инструкции, содержания и языка завершаются успешно

#### Scenario: Финал нарушает индивидуальное задание

- **WHEN** число слайдов, структура, обязательные факты, ограничения или язык финала не соответствуют YAML кейса
- **THEN** соответствующая индивидуальная проверка завершается ошибкой
- **AND** описывает проверяемое требование

### Requirement: Функциональная проверка происхождения медиафайлов

Сценарий клонирования презентации SHALL предоставлять переиспользуемую функциональную проверку, которая для кейса с запретом посторонних изображений сравнивает содержимое медиафайлов финального PPTX с медиафайлами приложенного шаблона.

#### Scenario: Все медиафайлы присутствуют в шаблоне

- **WHEN** каждый файл `ppt/media/*` финального PPTX имеет такое же содержимое, как хотя бы один медиафайл приложенного шаблона
- **THEN** проверка происхождения изображений завершается успешно независимо от имён файлов

#### Scenario: Добавлен посторонний медиафайл

- **WHEN** финальный PPTX содержит файл `ppt/media/*`, содержимое которого отсутствует в приложенном шаблоне
- **THEN** проверка происхождения изображений завершается ошибкой
- **AND** перечисляет посторонние медиафайлы

## MODIFIED Requirements

### Requirement: Функциональные проверки сценария клонирования презентации

Сценарий клонирования презентации SHALL поддерживать независимые функциональные проверки формата промежуточного описания стиля, соответствия этого описания приложенному шаблону, сохранения master/theme/layouts и отсутствия специфичных для каждого кейса запрещённых следов шаблона в видимых частях финала.

#### Scenario: Описание стиля имеет корректный заголовок

- **WHEN** промежуточный `STYLE.md` содержит распознаваемый заголовок с именем шаблона и числом слайдов
- **THEN** проверка формата заголовка завершается успешно без обязательного выбора PPTX

#### Scenario: Описание стиля ссылается на приложенный шаблон

- **WHEN** заголовок промежуточного `STYLE.md` содержит имя файла, совпадающее с приложенным шаблоном
- **THEN** проверка соответствия шаблону завершается успешно

#### Scenario: Описание стиля ссылается на другой файл

- **WHEN** заголовок промежуточного `STYLE.md` содержит имя, отличное от приложенного шаблона
- **THEN** проверка соответствия шаблону завершается ошибкой
- **AND** показывает ожидаемое и фактическое имена

#### Scenario: Оформление финала соответствует шаблону

- **WHEN** размер слайда, master/theme/layouts и использованные шрифты финала соответствуют приложенному шаблону
- **THEN** проверка сохранения оформления завершается успешно

#### Scenario: Финал содержит чужое оформление

- **WHEN** финал использует изменённые или чужие layouts, либо шрифт, отсутствующий в шаблоне
- **THEN** проверка сохранения оформления завершается ошибкой
- **AND** описывает отличие

#### Scenario: Видимые части финала содержат след шаблона

- **WHEN** слайды, заметки, метаданные или ссылки финала содержат запрещённые `terms/patterns` из YAML конкретного кейса
- **THEN** проверка чистоты завершается ошибкой
- **AND** перечисляет найденные совпадения

#### Scenario: Кейсы используют разные запрещённые следы

- **WHEN** кейсы используют разные исходные шаблоны или содержат разные инструкции, текст которых не должен попасть на слайды
- **THEN** каждый кейс применяет собственные `terms/patterns` без обязательной общей группы чистоты

#### Scenario: Следы в неиспользуемых служебных заготовках

- **WHEN** запрещённый текст находится только в неиспользуемом layout или внутреннем имени темы, сохранённых для целостности оформления
- **THEN** проверка чистоты не считает их видимым нарушением
