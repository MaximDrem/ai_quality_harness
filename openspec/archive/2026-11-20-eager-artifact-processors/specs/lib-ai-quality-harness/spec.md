## MODIFIED Requirements

### Requirement: Переиспользуемые процессоры артефактов

Система SHALL отделять чтение и рендер артефакта от логики проверок. До выполнения checks система SHALL передавать весь `ArtifactContext` в processor-оркестратор. Для каждого файлового `Artifact` система SHALL выбирать явно заданный processor или находить его по расширению, после чего processor SHALL сразу заполнять все свои атрибуты в том же объекте.

#### Scenario: Полная обработка до checks

- **WHEN** собран `ArtifactContext` с файловыми артефактами
- **THEN** processors извлекают все поддерживаемые text/raw_structure/rendered_photos до первого check
- **AND** checks только читают готовые атрибуты и не вызывают processors

#### Scenario: Существующий тип используется новым сценарием

- **WHEN** новый сценарий использует уже поддерживаемый тип артефакта
- **THEN** он использует существующий processor без копирования его реализации

#### Scenario: Процессор выбран явно

- **WHEN** артефакт задаёт processor в YAML
- **THEN** система использует его с приоритетом над автоматическим выбором по расширению

#### Scenario: Процессор выбран по расширению

- **WHEN** processor не задан явно
- **THEN** система выбирает processor, объявивший поддержку расширения файла

#### Scenario: Новый формат

- **WHEN** разработчик добавляет processor нового формата и ссылается на него из YAML
- **THEN** извлечение всех данных работает через новый processor без правки основного pipeline

#### Scenario: Ошибка одного атрибута

- **WHEN** извлечение rendered_photos завершилось ошибкой, а text и raw_structure извлечены
- **THEN** ошибка сохраняется в `Artifact.processing_errors` для rendered_photos
- **AND** успешно извлечённые остальные атрибуты остаются доступны checks

### Requirement: Роли и выбор артефактов

Система SHALL поддерживать роли `source`, `supporting`, `final` и `final_message` и позволять проверке выбирать артефакты по роли или уникальному имени из YAML. Финальный файл SHALL объявляться `is_final_result: true`; вспомогательный файл SHALL NOT требовать флага.

#### Scenario: Проверка промежуточного результата

- **WHEN** YAML использует удалённый `stage`
- **THEN** конфигурация отклоняется с указанием использовать `is_final_result`
- **AND** актуальный вспомогательный файл выбирается по имени либо роли `supporting`

#### Scenario: Проверка вспомогательного результата

- **WHEN** проверка ссылается на имя артефакта без `is_final_result`
- **THEN** она получает его актуальный файл и все извлечённые processors данные
- **AND** финальные файлы не добавляются без явного выбора

#### Scenario: Проверка исходного и финального результата

- **WHEN** проверка перечисляет исходное вложение и финальный артефакт
- **THEN** контекст проверки содержит оба файла с различимыми ролями

#### Scenario: Неуказанный селектор

- **WHEN** проверка не задаёт селектор артефактов
- **THEN** система передаёт ей финальные артефакты по умолчанию

#### Scenario: Вспомогательный файл не завершает кейс

- **WHEN** найден только файл без `is_final_result`
- **THEN** кейс не считается готовым
- **AND** система продолжает ожидать обязательный финальный результат

## REMOVED Requirements

### Requirement: Сохранение промежуточных версий

Автоматические snapshot’ы промежуточных версий удалены из базового контракта. Вспомогательные файлы предоставляют checks актуальное состояние; отдельная история версий не создаётся.
